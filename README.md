# Zarap

Zarap — LuCI-приложение для OpenWrt 25.12.x, которое заворачивает внешний IPv4 TCP/UDP-трафик локальной сети в `xray-core` и раздаёт его по правилам: устройство идёт через VLESS Reality, напрямую или блокируется. Для устройств, названных правилом, постоянно действует kill switch: при остановке или ошибке прокси прямой выход в WAN не открывается, и вернуть его может только удаление правила.

Текущий статус: реализация MVP. Перед использованием на основном роутере пакет необходимо проверить на тестовом устройстве с OpenWrt 25.12.x.

## Что реализовано

- импорт нескольких VLESS Reality TCP-ссылок, включая `xtls-rprx-vision`; каждая становится отдельным outbound;
- список правил, который преобразуется в `routing.rules` конфига `xray-core`: правило называет устройства и цель — подключение, `direct` или `block`;
- условия правила по назначению: домены, списки `.dat` (`geosite` и `geoip`), диапазоны IPv4, порты и протокол (`tcp`/`udp`), в любом сочетании с устройствами или без них;
- списки правил в формате `.dat` (V2Ray/Xray): для каждого списка задаётся URL (`https://`), тип (`geosite` или `geoip`) и категория внутри файла (например `youtube`, `ru-blocked`); разные категории из одного `.dat` скачивают файл один раз, а подключение и расписание автообновления (`ruleset_detour`, `ruleset_interval`) общие на все списки;
- по расписанию `.dat`-файлы в `/etc/zarap/assets` обновляет сам `xray-core` через встроенный блок `geodata` с горячей перезагрузкой без разрыва соединений; при первом применении недостающие `.dat` скачиваются заранее через выбранное подключение (напрямую через `curl` или через временный локальный SOCKS5-инстанс `xray`);
- принудительное обновление списков кнопкой на странице: прежние `.dat` откладываются в резервную копию, новые скачиваются и проверяются через `xray run -test`, после чего `xray` перезапускается; при ошибке или отсутствии нужной категории прежние файлы возвращаются на место;
- маршрутизация DNS без петель и утечек: домены, отправленные правилом в подключение, резолвятся через него же (`disableFallbackIfMatch: true`, `skipFallback` + `finalQuery`); для каждого подключения с ручными доменами открывается отдельный локальный DNS-слушатель (`127.0.0.1:5353`, `5354`, …) и свой `dns-out`, где `A`/`AAAA` перехватываются во встроенный DNS `xray-core`, а остальные типы (`TXT`, `MX`, `SRV`, `HTTPS`) уходят внутрь соответствующего туннеля через `dialerProxy` — без ложных пустых ответов и без утечек в открытый UDP/53; резолвер выбирается настройкой, по умолчанию DoH `https://1.1.1.1/dns-query`;
- bootstrap DNS для имён, которые роутер набирает сам: адрес сервера, записанный в ссылке доменом, и хост источника `.dat` при прямом скачивании защищены первым правилом `dns.servers` (`full:<домен>`, `skipFallback` + `finalQuery`) и резолвятся мимо туннеля;
- выбор этого резолвера на странице: по умолчанию `local` (`localhost` роутера), либо `https://` (DoH), `tcp://` и `udp://` по IPv4 (`tls://` / DoT встроенный DNS `xray-core` не поддерживает);
- отказ резолвера назван вслух: страница пишет, какое имя не разрешилось и каким резолвером, — иначе это выглядит как полное здоровье, потому что соединения устанавливаются, а ошибок в журнале нет;
- переключатель «резолвить имена через подключение»: Zarap забирает у dnsmasq весь DNS сети — домены из правил **и `geosite`-списков `.dat`** резолвятся через подключение, остальное напрямую. Нужен там, где имена подменяет кто-то ещё (соседний роутер с FakeIP, провайдер); без него списки `.dat` остаются без DNS вовсе, потому что тысячи имён в dnsmasq не перечислить. Прежние настройки dnsmasq запоминаются и возвращаются **при выключении Zarap**, а не только при удалении пакета;
- цель для остального трафика (`direct` по умолчанию), выраженная замыкающим правилом по `zarap-tproxy`;
- захват всего исходящего трафика LAN по интерфейсу `br-lan`, а не по списку адресов;
- запрет private/randomized MAC;
- static DHCP lease для каждого устройства из правил: адрес в правиле опирается на него;
- TProxy на `0.0.0.0:7893`, mark `0x5a52`, policy routing table `2022`;
- IPv4 kill switch для устройств из правил и блокировка внешнего IPv6 для всей LAN;
- отключение RA и DHCPv6 на lan-интерфейсе, с восстановлением прежних значений при удалении пакета;
- прямой доступ к роутеру, LAN, multicast и broadcast мимо захвата;
- kill switch остаётся и при выключенном Zarap: устройство с правилом не получает прямой выход в WAN, пока правило не удалено;
- транзакционное применение через временный UCI-кандидат с проверками `xray run -test` и `nft -c`;
- проверка после запуска: процесс `xray`, TProxy-порт, nftables и policy routing, с восстановлением предыдущей конфигурации при сбое;
- отдельные статусы ошибок ввода, совместимости, запуска и соединения;
- обнаружение устройств всей локальной сети: static и текущие DHCP leases как основа, hostapd добавляет признак «в сети» и радиоинтерфейс;
- редактирование подключений, правил и списков в LuCI: добавление, удаление, перестановка, выбор устройств, условий по назначению и цели;
- отдельная проверка и обновление пакетов `luci-app-zarap` и `xray-core`;
- очистка журнала и RPC-ответов от UUID и Reality public key всех подключений.

Zarap не закреплён за конкретной версией `xray-core`: пакет получает совместимую версию из штатных репозиториев OpenWrt и проверяет существующий конфиг после обновления бинарника.

## Установка собранного APK через LuCI

Основной способ установки — подписанный APK-репозиторий, описанный ниже. Если репозиторий по каким-то причинам недоступен, APK можно собрать в OpenWrt SDK или взять из GitHub Release и установить вручную:

1. Откройте **LuCI → Система → Программы**.
2. Нажмите **Загрузить пакет**.
3. Выберите собранный `luci-app-zarap-*.apk` на компьютере.
4. Подтвердите установку вместе с зависимостями.
5. Откройте **Службы → Zarap**.

Подписанный APK-репозиторий опубликован на GitHub Pages по адресу:

```text
https://aiadr.github.io/Zarap/packages.adb
```

Публичный ключ опубликован как `https://aiadr.github.io/Zarap/zarap-apk.pem`. Перед первым подключением репозитория установите его через терминал роутера с обязательной проверкой SHA-256:

```sh
wget -O /tmp/zarap-apk.pem \
  https://aiadr.github.io/Zarap/zarap-apk.pem

echo 'd7ef4639a8fadbd7775e78b6cd394516707bee449cd10c410492fd03bcf00fd1  /tmp/zarap-apk.pem' | sha256sum -c - &&
mkdir -p /etc/apk/keys &&
cp /tmp/zarap-apk.pem /etc/apk/keys/zarap-apk.pem &&
chmod 0644 /etc/apk/keys/zarap-apk.pem &&
rm -f /tmp/zarap-apk.pem
```

Если проверка SHA-256 не пройдёт, ключ не будет скопирован в доверенное хранилище.

После установки проверенного ключа пользователь один раз добавляет URL `https://aiadr.github.io/Zarap/packages.adb` в `/etc/apk/repositories.d/customfeeds.list` через **LuCI → Система → Программы → Настроить apk**, сохраняет настройки, обновляет списки и устанавливает `luci-app-zarap`. Последующие обновления доступны штатно через LuCI и через страницу Zarap. Установка напрямую по URL GitHub Release остаётся только аварийным способом.

## Релизы и обновления

Публикация полностью автоматическая: **каждый коммит в `main` собирает пакет и выкладывает новую версию** в подписанный репозиторий и в GitHub Releases. Отдельного действия для выпуска релиза не требуется, теги вручную не расставляются.

Версия складывается из даты сборки по UTC и счётчика релизов за этот день:

```text
2026.08.05-r1    первый релиз 5 августа
2026.08.05-r2    второй релиз в тот же день
2026.08.06-r1    следующий день, счётчик сбрасывается
```

`PKG_VERSION` и `PKG_RELEASE` в `luci-app-zarap/Makefile` — плейсхолдер для локальных сборок и CI: настоящие значения подставляются в момент релизной сборки и в репозиторий не коммитятся. Тег `v<версия>` создаётся автоматически вместе с GitHub Release.

Из этого следует несколько вещей, о которых стоит знать:

- фильтра по путям нет, поэтому новая версия выходит и на коммиты, которые меняют только тесты, CI или документацию — код пакета при этом идентичен предыдущему;
- на роутерах с подключённым репозиторием такие сборки видны как доступное обновление;
- в подписанном индексе хранятся **десять последних версий** — на них можно откатиться через `apk`, всё более старое остаётся только в GitHub Releases.

## Использование

1. Вставьте VLESS Reality-ссылку в поле **Добавить подключение**.
2. Нажмите **Добавить правило**, выберите устройства кнопкой **Устройства…**, при необходимости укажите назначение кнопкой **Куда…** — домены, диапазоны адресов, порты, протокол и списки — и цель: подключение, «напрямую» или «заблокировать». Порядок правил задаётся стрелками, применяется первое подходящее.
3. Для устройств из правил проверьте статический IPv4 в таблице устройств: оставьте текущий адрес клиента или укажите свободный в LAN-подсети.
4. При необходимости смените цель для остального трафика в строке под таблицей правил.
5. Включите общий переключатель.
6. Нажмите **Проверить конфигурацию**, затем **Сохранить и применить**.
7. Если адрес клиента изменился из-за созданного static lease, переподключите его к сети вручную.

Правки на странице никуда не уходят до нажатия **Сохранить и применить**: до этого меняется только состояние в браузере.

По расписанию списки `.dat` обновляет `xray-core` сам (блок `geodata`) с горячей перезагрузкой. Кнопка **Обновить списки сейчас** нужна там, где ждать расписания нечего: список поправили на источнике или он не скачался, пока роутер был без интернета. Новые `.dat`-файлы скачиваются и проверяются `xray run -test` перед перезапуском; если источник оказался недоступен или в новом файле отсутствует нужная категория, прежние файлы возвращаются на место, а страница сообщает об ошибке.

Пример конфигурации `/etc/config/zarap`:

```
config zarap 'main'
	option enabled '1'
	option final 'direct'
	option ruleset_detour 'out_1'
	option ruleset_interval '1d'
	option bootstrap_dns 'https://1.1.1.1/dns-query'
	option resolve_all '1'
	option tunnel_dns 'https://1.1.1.1/dns-query'

config outbound 'out_1'
	option label 'Нидерланды'
	option type 'vless'
	option server 'nl.example.net'
	...

config rule
	list client '00:11:22:33:44:55'
	option target 'out_1'

config rule
	list client '10:20:30:40:50:60'
	option target 'block'

config ruleset 'rs_1'
	option label 'Реклама'
	option url 'https://example.org/geosite.dat'
	option kind 'geosite'
	option category 'category-ads-all'

config rule
	list rule_set 'rs_1'
	option target 'block'

config rule
	list domain 'youtube.com'
	list domain '.googlevideo.com'
	list ip_cidr '149.154.160.0/20'
	list port '443'
	option network 'udp'
	option target 'block'
```

Запись `youtube.com` покрывает и само имя, и поддомены; `.googlevideo.com` —
только поддомены.

Условия правила складываются так: устройства — «или» между собой, назначение и
уточнения — «и» ко всему остальному. Правило без устройств действует на весь
LAN, правило без назначения — на весь трафик названных устройств; хотя бы одно
условие у правила быть обязано. Под kill switch попадают только устройства,
названные в `list client`, — и попадают целиком, какую бы часть их трафика
правило ни описывало.

## Сборка

Репозиторий имеет структуру standalone LuCI feed package. Добавьте его в OpenWrt SDK или buildroot как пакет `luci-app-zarap` и выполните:

```sh
make package/luci-app-zarap/compile V=s
```

Пакет архитектурно независимый (`all`), но его зависимости должны существовать в репозиториях целевой сборки OpenWrt 25.12.x.

## Локальные тесты

Все юнит-, контрактные и браузерные тесты написаны на Node.js 22 (без Python) и pnpm 11 (`corepack enable`).

```sh
pnpm install
pnpm test
```

Браузерные тесты LuCI запускают изолированный Chromium и подменяют только RPC-ответы роутера:

```sh
pnpm exec playwright install chromium
pnpm test:browser
```

Для наблюдения за тестами в окне браузера:

```sh
pnpm test:browser:headed
```

Проверяются генерация конфига `xray-core` (включая отсутствие утечек и петель DNS), nftables, разбор VLESS-ссылок, отрисовка статусов и устройств, запрет private MAC, состав запросов `validate`/`apply`, вывод backend-ошибок, совместная проверка версий Zarap и `xray-core` и отдельное подтверждение каждого обновления. Моковый стенд не проверяет настоящий rpcd, UCI, nftables или TProxy — это остаётся задачей интеграционного теста OpenWrt в QEMU и финальной проверки на роутере.

## Постоянные файлы и службы

- `/etc/config/zarap` — единственный источник настроек Zarap, режим `0600`;
- `/etc/zarap/xray.json` — сгенерированный конфиг `xray-core`;
- `/etc/zarap/xray.json.bak` — последняя резервная копия;
- `/etc/zarap/assets/` — каталог `.dat`-файлов списков (`XRAY_LOCATION_ASSET`);
- `/etc/nftables.d/90-zarap.nft` — автоматически подключаемые firewall4 правила;
- `/etc/init.d/zarap` — восстановление policy routing;
- `/etc/init.d/xray` — штатная служба OpenWrt, запускающая сгенерированный конфиг.

## Ограничения

- только VLESS Reality поверх TCP;
- имя сервера из ссылки резолвится мимо прокси: по умолчанию через резолвер самого роутера, и этот запрос провайдер видит. Скрыть его можно, выбрав `https://` (DoH) на странице, но такой резолвер должен быть доступен — иначе подключение не поднимется вовсе;
- правило по домену действует на соединения, где имя видно в запросе; домен, отправленный в подключение, резолвится через него, а домен с целью `direct` или `block` — нет, и от блокировки в DNS такое правило не спасает;
- редактирование правил по-прежнему не покрывает группы подключений (`selector`/`urltest`) — они спланированы в [`docs/routing-design.md`](docs/routing-design.md);
- проксирование только IPv4 TCP/UDP; IPv6 в локальной сети не раздаётся и не маршрутизируется наружу;
- private/randomized MAC не поддерживаются;
- отказ `xray` при включённом Zarap оставляет без интернета всю локальную сеть, а не только устройства с правилами;
- с включённым «резолвить имена через подключение» отказ `xray` забирает у сети ещё и внешние имена: dnsmasq спрашивает только его. Локальные имена он отвечает сам, и прежние настройки возвращаются, как только Zarap выключен;
- захваченный трафик проходит через userspace и не обрабатывается flow offload;
- фоновые обновления и общий `apk upgrade` не выполняются.

Исходный дизайн модели правил и маршрутизации (до миграции на `xray-core`) описан в [`docs/routing-design.md`](docs/routing-design.md) и [`docs/rule-conditions-design.md`](docs/rule-conditions-design.md).
