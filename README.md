# Zarap

Zarap — LuCI-приложение для OpenWrt 25.12.x, которое направляет внешний IPv4 TCP/UDP-трафик выбранных Wi-Fi-устройств через VLESS Reality в `sing-box`. Для выбранных устройств постоянно действует kill switch: при остановке или ошибке прокси прямой выход в WAN не открывается.

Текущий статус: реализация MVP. Перед использованием на основном роутере пакет необходимо проверить на тестовом устройстве с OpenWrt 25.12.x.

## Что реализовано

- импорт одной VLESS Reality TCP-ссылки, включая `xtls-rprx-vision`;
- выбор клиентов активных Wi-Fi-интерфейсов;
- запрет private/randomized MAC;
- сохранение или создание static DHCP lease до включения проксирования;
- TProxy на `0.0.0.0:7893`, mark `0x5a52`, policy routing table `2022`;
- IPv4 kill switch и блокировка внешнего IPv6 по MAC;
- прямой доступ выбранных клиентов к роутеру, LAN, multicast и broadcast;
- транзакционное применение через временный UCI-кандидат с проверками `sing-box check` и `nft -c`;
- проверка после запуска: процесс sing-box, TProxy-порт, nftables и policy routing, с восстановлением предыдущей конфигурации при сбое;
- отдельные статусы ошибок ввода, совместимости, запуска и соединения;
- обнаружение Wi-Fi-клиентов через hostapd с объединением static и текущих DHCP leases;
- отдельная проверка и обновление пакетов `luci-app-zarap` и `sing-box`;
- очистка журнала и RPC-ответов от UUID и Reality public key.

Zarap не закреплён за конкретной версией `sing-box`: пакет получает совместимую версию из штатных репозиториев OpenWrt и проверяет существующий конфиг после обновления бинарника.

## Установка собранного APK через LuCI

До публикации подписанного репозитория APK можно собрать в OpenWrt SDK и установить вручную:

1. Откройте **LuCI → Система → Программы**.
2. Нажмите **Загрузить пакет**.
3. Выберите собранный `luci-app-zarap-*.apk` на компьютере.
4. Подтвердите установку вместе с зависимостями.
5. Откройте **Службы → Zarap**.

Основным релизным способом станет подписанный APK-репозиторий на GitHub Pages. После первого подписанного релиза его адрес будет:

```text
https://aiadr.github.io/Zarap/packages.adb
```

Публичный ключ опубликован как `https://aiadr.github.io/Zarap/zarap-apk.pem`. Перед первым подключением репозитория установите его через терминал роутера с обязательной проверкой SHA-256:

```sh
wget -O /tmp/zarap-apk.pem \
  https://aiadr.github.io/Zarap/zarap-apk.pem

echo 'e8e7b1090d190d7039b01afcd84164727923a8b103fcb12e282849d0dd3b2cbb  /tmp/zarap-apk.pem' | sha256sum -c - &&
mkdir -p /etc/apk/keys &&
cp /tmp/zarap-apk.pem /etc/apk/keys/zarap-apk.pem &&
chmod 0644 /etc/apk/keys/zarap-apk.pem &&
rm -f /tmp/zarap-apk.pem
```

Если проверка SHA-256 не пройдёт, ключ не будет скопирован в доверенное хранилище.

После установки проверенного ключа пользователь один раз добавляет URL `https://aiadr.github.io/Zarap/packages.adb` в `/etc/apk/repositories.d/customfeeds.list` через **LuCI → Система → Программы → Настроить apk**, сохраняет настройки, обновляет списки и устанавливает `luci-app-zarap`. Последующие обновления доступны штатно через LuCI и через страницу Zarap. Установка напрямую по URL GitHub Release остаётся только аварийным способом.

## Использование

1. Вставьте VLESS Reality-ссылку.
2. Выберите Wi-Fi-устройства. Для нового static lease оставьте текущий IPv4 клиента или укажите свободный адрес в LAN-подсети.
3. Включите общий переключатель.
4. Нажмите **Проверить конфигурацию**, затем **Сохранить и применить**.
5. Если адрес клиента изменился из-за созданного static lease, переподключите его к Wi-Fi вручную.

Поле VLESS можно оставить пустым при последующих изменениях списка устройств: сохранённые секреты не возвращаются в браузер.

## Сборка

Репозиторий имеет структуру standalone LuCI feed package. Добавьте его в OpenWrt SDK или buildroot как пакет `luci-app-zarap` и выполните:

```sh
make package/luci-app-zarap/compile V=s
```

Пакет архитектурно независимый (`all`), но его зависимости должны существовать в репозиториях целевой сборки OpenWrt 25.12.x.

## Локальные браузерные тесты

Быстрые тесты LuCI запускают изолированный Chromium и подменяют только RPC-ответы роутера. Физическое устройство и OpenWrt для них не нужны. Требуются Node.js 22 и pnpm 11; pnpm можно включить командой `corepack enable`.

```sh
pnpm install
pnpm exec playwright install chromium
pnpm test:browser
```

Для наблюдения за тестами в окне браузера:

```sh
pnpm test:browser:headed
```

Проверяются отрисовка статусов и устройств, запрет private MAC, состав запросов `validate`/`apply`, вывод backend-ошибок, совместная проверка версий Zarap и sing-box и отдельное подтверждение каждого обновления. Моковый стенд не проверяет настоящий rpcd, UCI, nftables или TProxy — это остаётся задачей интеграционного теста OpenWrt в QEMU и финальной проверки на роутере.

## Постоянные файлы и службы

- `/etc/config/zarap` — единственный источник настроек Zarap, режим `0600`;
- `/etc/zarap/sing-box.json` — сгенерированный конфиг;
- `/etc/zarap/sing-box.json.bak` — последняя резервная копия;
- `/etc/nftables.d/90-zarap.nft` — автоматически подключаемые firewall4 правила;
- `/etc/init.d/zarap` — восстановление policy routing;
- `/etc/init.d/sing-box` — штатная служба OpenWrt, запускающая сгенерированный конфиг.

## Ограничения MVP

- только VLESS Reality поверх TCP;
- один outbound;
- проксирование только IPv4 TCP/UDP;
- внешний IPv6 выбранных устройств блокируется, а не проксируется;
- private/randomized MAC не поддерживаются;
- фоновые обновления и общий `apk upgrade` не выполняются.
