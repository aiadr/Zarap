# Zarap

Zarap — LuCI-приложение для OpenWrt 25.12.x, которое заворачивает внешний IPv4 TCP/UDP-трафик локальной сети в `sing-box` и раздаёт его по правилам: устройство идёт через VLESS Reality, напрямую или блокируется. Для устройств, названных правилом, постоянно действует kill switch: при остановке или ошибке прокси прямой выход в WAN не открывается, и вернуть его может только удаление правила.

Текущий статус: реализация MVP. Перед использованием на основном роутере пакет необходимо проверить на тестовом устройстве с OpenWrt 25.12.x.

## Что реализовано

- импорт нескольких VLESS Reality TCP-ссылок, включая `xtls-rprx-vision`; каждая становится отдельным outbound;
- список правил, который преобразуется в `route.rules` конфига sing-box: правило называет устройства и цель — подключение, `direct` или `block`;
- цель для остального трафика (`direct` по умолчанию), выраженная в `route.final`;
- захват всего исходящего трафика LAN по интерфейсу `br-lan`, а не по списку адресов;
- запрет private/randomized MAC;
- static DHCP lease для каждого устройства из правил: адрес в правиле опирается на него;
- TProxy на `0.0.0.0:7893`, mark `0x5a52`, policy routing table `2022`;
- IPv4 kill switch для устройств из правил и блокировка внешнего IPv6 для всей LAN;
- отключение RA и DHCPv6 на lan-интерфейсе, с восстановлением прежних значений при удалении пакета;
- прямой доступ к роутеру, LAN, multicast и broadcast мимо захвата;
- kill switch остаётся и при выключенном Zarap: устройство с правилом не получает прямой выход в WAN, пока правило не удалено;
- транзакционное применение через временный UCI-кандидат с проверками `sing-box check` и `nft -c`;
- проверка после запуска: процесс sing-box, TProxy-порт, nftables и policy routing, с восстановлением предыдущей конфигурации при сбое;
- отдельные статусы ошибок ввода, совместимости, запуска и соединения;
- обнаружение устройств всей локальной сети: static и текущие DHCP leases как основа, hostapd добавляет признак «в сети» и радиоинтерфейс;
- редактирование подключений и правил в LuCI: добавление, удаление, перестановка, выбор устройств и цели;
- отдельная проверка и обновление пакетов `luci-app-zarap` и `sing-box`;
- очистка журнала и RPC-ответов от UUID и Reality public key всех подключений.

Zarap не закреплён за конкретной версией `sing-box`: пакет получает совместимую версию из штатных репозиториев OpenWrt и проверяет существующий конфиг после обновления бинарника.

## Установка собранного APK через LuCI

Основной способ установки — подписанный APK-репозиторий, описанный ниже. Если репозиторий по каким-то причинам недоступен, APK можно собрать в OpenWrt SDK или взять из GitHub Release и установить вручную:

1. Откройте **LuCI → Система → Программы**.
2. Нажмите **Загрузить пакет**.
3. Выберите собранный `luci-app-zarap-*.apk` на компьютере.
4. Подтвердите установку вместе с зависимостями.
5. Откройте **Службы → Zarap**.

Подписанный APK-репозиторий опубликован на GitHub Pages по адресу:

```text
https://aiadr.github.io/Zarap/packages.adb
```

Публичный ключ опубликован как `https://aiadr.github.io/Zarap/zarap-apk.pem`. Перед первым подключением репозитория установите его через терминал роутера с обязательной проверкой SHA-256:

```sh
wget -O /tmp/zarap-apk.pem \
  https://aiadr.github.io/Zarap/zarap-apk.pem

echo 'd7ef4639a8fadbd7775e78b6cd394516707bee449cd10c410492fd03bcf00fd1  /tmp/zarap-apk.pem' | sha256sum -c - &&
mkdir -p /etc/apk/keys &&
cp /tmp/zarap-apk.pem /etc/apk/keys/zarap-apk.pem &&
chmod 0644 /etc/apk/keys/zarap-apk.pem &&
rm -f /tmp/zarap-apk.pem
```

Если проверка SHA-256 не пройдёт, ключ не будет скопирован в доверенное хранилище.

После установки проверенного ключа пользователь один раз добавляет URL `https://aiadr.github.io/Zarap/packages.adb` в `/etc/apk/repositories.d/customfeeds.list` через **LuCI → Система → Программы → Настроить apk**, сохраняет настройки, обновляет списки и устанавливает `luci-app-zarap`. Последующие обновления доступны штатно через LuCI и через страницу Zarap. Установка напрямую по URL GitHub Release остаётся только аварийным способом.

## Релизы и обновления

Публикация полностью автоматическая: **каждый коммит в `main` собирает пакет и выкладывает новую версию** в подписанный репозиторий и в GitHub Releases. Отдельного действия для выпуска релиза не требуется, теги вручную не расставляются.

Версия складывается из даты сборки по UTC и счётчика релизов за этот день:

```text
2026.08.05-r1    первый релиз 5 августа
2026.08.05-r2    второй релиз в тот же день
2026.08.06-r1    следующий день, счётчик сбрасывается
```

`PKG_VERSION` и `PKG_RELEASE` в `luci-app-zarap/Makefile` — плейсхолдер для локальных сборок и CI: настоящие значения подставляются в момент релизной сборки и в репозиторий не коммитятся. Тег `v<версия>` создаётся автоматически вместе с GitHub Release.

Из этого следует несколько вещей, о которых стоит знать:

- фильтра по путям нет, поэтому новая версия выходит и на коммиты, которые меняют только тесты, CI или документацию — код пакета при этом идентичен предыдущему;
- на роутерах с подключённым репозиторием такие сборки видны как доступное обновление;
- в подписанном индексе хранятся **десять последних версий** — на них можно откатиться через `apk`, всё более старое остаётся только в GitHub Releases.

## Использование

1. Вставьте VLESS Reality-ссылку в поле **Добавить подключение**.
2. Нажмите **Добавить правило**, выберите устройства кнопкой **Устройства…** и укажите цель: подключение, «напрямую» или «заблокировать». Порядок правил задаётся стрелками, применяется первое подходящее.
3. Для устройств из правил проверьте статический IPv4 в таблице устройств: оставьте текущий адрес клиента или укажите свободный в LAN-подсети.
4. При необходимости смените цель для остального трафика в строке под таблицей правил.
5. Включите общий переключатель.
6. Нажмите **Проверить конфигурацию**, затем **Сохранить и применить**.
7. Если адрес клиента изменился из-за созданного static lease, переподключите его к сети вручную.

Правки на странице никуда не уходят до нажатия **Сохранить и применить**: до этого меняется только состояние в браузере.

Поле подключения можно оставить пустым при последующих изменениях: сохранённые подключения отправляются обратно по тегу, а их секреты не возвращаются в браузер.

Пример конфигурации:

```
config zarap 'main'
	option enabled '1'
	option final 'direct'

config outbound 'out_1'
	option label 'Нидерланды'
	option type 'vless'
	option server 'nl.example.net'
	...

config rule
	list client '00:11:22:33:44:55'
	option target 'out_1'

config rule
	list client '10:20:30:40:50:60'
	option target 'block'
```

## Сборка

Репозиторий имеет структуру standalone LuCI feed package. Добавьте его в OpenWrt SDK или buildroot как пакет `luci-app-zarap` и выполните:

```sh
make package/luci-app-zarap/compile V=s
```

Пакет архитектурно независимый (`all`), но его зависимости должны существовать в репозиториях целевой сборки OpenWrt 25.12.x.

## Локальные браузерные тесты

Быстрые тесты LuCI запускают изолированный Chromium и подменяют только RPC-ответы роутера. Физическое устройство и OpenWrt для них не нужны. Требуются Node.js 22 и pnpm 11; pnpm можно включить командой `corepack enable`.

```sh
pnpm install
pnpm exec playwright install chromium
pnpm test:browser
```

Для наблюдения за тестами в окне браузера:

```sh
pnpm test:browser:headed
```

Проверяются отрисовка статусов и устройств, запрет private MAC, состав запросов `validate`/`apply`, вывод backend-ошибок, совместная проверка версий Zarap и sing-box и отдельное подтверждение каждого обновления. Моковый стенд не проверяет настоящий rpcd, UCI, nftables или TProxy — это остаётся задачей интеграционного теста OpenWrt в QEMU и финальной проверки на роутере.

## Постоянные файлы и службы

- `/etc/config/zarap` — единственный источник настроек Zarap, режим `0600`;
- `/etc/zarap/sing-box.json` — сгенерированный конфиг;
- `/etc/zarap/sing-box.json.bak` — последняя резервная копия;
- `/etc/nftables.d/90-zarap.nft` — автоматически подключаемые firewall4 правила;
- `/etc/init.d/zarap` — восстановление policy routing;
- `/etc/init.d/sing-box` — штатная служба OpenWrt, запускающая сгенерированный конфиг.

## Ограничения

- только VLESS Reality поверх TCP;
- условия правил — пока только по устройствам; условия по доменам, адресам и портам запланированы;
- проксирование только IPv4 TCP/UDP; IPv6 в локальной сети не раздаётся и не маршрутизируется наружу;
- private/randomized MAC не поддерживаются;
- отказ sing-box при включённом Zarap оставляет без интернета всю локальную сеть, а не только устройства с правилами;
- захваченный трафик проходит через userspace и не обрабатывается flow offload;
- фоновые обновления и общий `apk upgrade` не выполняются.

Модель, схема uci, маппинг на `outbounds` и `route.rules`, принятые решения и
следующие этапы описаны в [`docs/routing-design.md`](docs/routing-design.md).
